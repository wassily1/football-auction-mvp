# 朋友杯球员竞拍系统

一个为 6–7 位朋友设计的轻量足球球员竞拍 Web 应用。管理员负责分配资金、选择拍品和开启竞拍；参与者可以在自己的电脑或手机上同步查看倒计时、球员属性和竞价席，并实时报价。成交球员会自动进入球队阵容。

项目内置 312 名球员及本地照片，使用 Python 标准库和 SQLite，不需要安装第三方依赖。

## 功能概览

### 管理员

- 使用初始管理员账号登录。
- 查看参与球队并直接设置资金。
- 以统一列表只读查看每支参与球队的阵容和球员详情。
- 通过明确的编辑状态调整资金，并可释放参与者账号。
- 搜索指定球员加入拍卖池。
- 按评分、主位置和球员类别随机抽卡。
- 设置明拍或暗拍、起拍价、最小加价和倒计时。
- 控制拍卖池中球员的开拍顺序。
- 可从竞价市场右下角直接选择球员并立即开拍；进行中的球员会保留在待拍池顶部。
- 可主动落槌成交，或撤回拍卖并清空本轮报价、将球员退回待拍池。
- 实时查看参与球队、报价历史和当前领先者。

### 参与者

- 自助创建账号和自定义球队，初始资金为 0。
- 查看完整球员信息：照片、位置、六项能力、六边形图、花式、逆足和金银能力。
- 按页浏览球员库，并按位置、国籍和俱乐部筛选。
- 实时同步竞拍倒计时、最高报价、竞价席和报价历史；报价提交前会显示金额确认。
- 明拍允许被超价后再次举牌，当前最高报价方不能自我加价；暗拍每支球队只能提交一次密封报价。
- 编辑自己的球队名称。
- 以列表查看阵容，按位置、国籍和成交价分组排序，并打开球员详情。

### 拍卖流程

1. 参与者创建账号和球队。
2. 管理员为各球队分配资金。
3. 管理员搜索球员或随机抽卡，将球员加入拍卖池；也可以通过市场快捷入口直接开拍。
4. 管理员开启竞拍，所有在线设备同步看到倒计时（默认 30 秒，可按拍品配置）。
5. 参与者报价；每次有效报价都会按本拍品配置重新开始倒计时。明拍实时更新领先球队，暗拍仅显示已报价球队数量。
6. 倒计时结束后自动成交或流拍；管理员也可以提前落槌，或撤回本轮拍卖。
7. 成交金额从球队资金中扣除，球员自动进入该球队替补席。

### 实时同步与报价一致性

- 服务端通过 SSE 事件流主动通知所有在线客户端，客户端收到事件后立即获取服务端最新拍卖状态；15 秒低频刷新仅作为断线兜底。
- 倒计时由服务端时间校准，浏览器在两次事件之间以 100ms 频率平滑渲染红色进度环。
- 报价、开拍、到期结算和最高价球队资金调整共用同一把竞拍状态锁，避免临界时刻并行修改。
- 每次报价都会在锁内重新校验竞拍时间、账号与球队、当前领先者、最低有效报价、余额和暗拍次数，事务提交后才向其他客户端广播。

## 一键启动

### macOS

下载项目后，直接双击 `start.command`。

如果系统第一次阻止执行，在终端运行一次：

```bash
chmod +x start.command start.sh
./start.command
```

### Linux

```bash
chmod +x start.sh
./start.sh
```

### Windows

双击 `start.bat`，或在命令提示符中运行：

```bat
start.bat
```

启动成功后，本机访问：

```text
http://127.0.0.1:8080
```

默认管理员：

```text
账号：admin
密码：admin123
```

## 让其他电脑或手机访问

应用默认监听 `0.0.0.0:8080`，同一 Wi-Fi 或局域网中的设备可以直接访问运行电脑的局域网 IP：

```text
http://运行电脑的局域网IP:8080
```

例如运行电脑的 IP 是 `192.168.1.23`：

```text
http://192.168.1.23:8080
```

注意事项：

- 所有设备需要处于同一局域网。
- macOS 或 Windows 首次启动时，需要允许 Python 接受网络连接。
- 路由器开启了“访客网络隔离”时，不同设备可能无法互相访问。
- 8080 端口被占用时，可以通过环境变量更换端口。

## 从 GitHub 启动

```bash
git clone https://github.com/wassily1/football-auction-mvp.git
cd football-auction-mvp
./start.sh
```

只要电脑安装了 Python 3.10 或更高版本，就不需要执行 `pip install`。

## 配置

支持以下环境变量：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `AUCTION_HOST` | `0.0.0.0` | 服务监听地址 |
| `AUCTION_PORT` | `8080` | 服务监听端口 |
| `AUCTION_ADMIN_PASSWORD` | `admin123` | 初始管理员密码 |

示例：

```bash
AUCTION_PORT=9000 AUCTION_ADMIN_PASSWORD='new-password' ./start.sh
```

启动后访问 `http://127.0.0.1:9000`。

## 数据与备份

- 球员数据库快照：`data/players.json`
- 球员照片：`static/player-images/`
- 运行数据：`data/auction.db`

账号、球队、资金、拍卖和阵容都保存在 `data/auction.db`。备份时停止服务，然后复制该文件即可。

重置全部比赛数据：

1. 停止服务。
2. 将 `data/auction.db` 移走或删除。
3. 再次启动应用。

球员快照和照片不会受到影响。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖账号权限、资金分配、多人同时报价、报价续时、暗拍金额隐藏与单次报价、直接开拍、自动/人工成交、撤回清价、资金扣除、球队改名、账号释放和管理员跨球队阵容查看。

## 当前范围

这是面向朋友内部使用的轻量版本，重点保证完整正向流程。当前没有实现教练拍卖、复杂版本回滚、互联网级安全防护和高并发部署。

如果需要通过公网开放，请至少修改管理员密码，并在应用前增加 HTTPS 反向代理；不要直接将默认账号和 8080 端口暴露到公网。
